## 1. 총평

작업지시서 v1은 기획서 v1.3의 §12 Phase 1을 충실히 분해하였다. 특히 (a) 감사 기록 체계(WP-6)를 회원 관리(WP-5)의 선행 조건으로 배치한 점, (b) 최고관리자 보존 검사의 동시 요청 경쟁 테스트를 DoD에 명시한 점, (c) CI 게이트를 작업 패키지별 가동 시점으로 구분하려 시도한 점은 기획서의 의도를 정확히 소화한 것이다.

다만 아래 발견 사항 중 **RT-1은 기획서 차원의 파생 결함이 작업지시서의 성공 기준으로 굳어진 건**으로, 발주자 결정(§3)이 이미 내려졌으므로 v2에 반드시 반영해야 한다. RT-2·RT-3은 이행 시 규칙 위반(INV-6) 또는 검수 불능이 발생하는 실질 결함이다.

## 2. 발견 사항 (심각도 순)

### [RT-1 · 중대] 탈취된 `SUPER_ADMIN`의 시스템 내 무력화 경로 부재 — 그리고 작업지시서가 이를 "성공"으로 실증하도록 지시함

- **위치**: WP-5 작업 항목 7·8, WP-5 DoD 2항("동급 관리자 상호 공격 → 거부"), 기획서 §4.6-1
- **결함**: 우위 검사(동집합 거부)와 본인 대상 금지의 파생 결과로, `SUPER_ADMIN` 역할은 부여 이후 시스템의 어떤 정상 경로로도 회수·정지가 불가능하다. `SUPER_ADMIN` A가 탈취되어도 다른 `SUPER_ADMIN` B는 A와 권한 집합이 동일하여 우위 검사에서 거부된다.
- **실패 시나리오**: `SUPER_ADMIN` 계정 1개 탈취 → 공격자는 전체 권한으로 활동 → 나머지 최고관리자들은 API로 아무 조치 불가 → 유일한 대응이 기획서 §16.3-1이 금지한 "운영 DB 직접 수정"이 됨.
- **v2 반영 지시** (발주자 결정 반영 — §3 참조):
  - WP-5 DoD에 현행 "동급 상호 공격 → 거부" 실증은 유지하되, **"단, `SUPER_ADMIN` 무력화는 break-glass 절차로만 가능함"을 명시한 주석**을 단다.
  - **WP-6 또는 별도 WP에 break-glass 런북 산출물을 추가**한다: 2인 입회, 전용 DB 계정(평시 비활성), 실행 전·후 전량 감사 기록, 실행 후 전 세션 강제 무효화(pv 전체 증가) 절차. 런북 문서는 저장소 `docs/`에 편입하고 Phase 1 완료 기준(WP-8 DoD)에 포함한다.
  - 쿼럼 승인 구조는 Phase 3 확장이므로 작업지시서 범위 제외 항목(§1.2)에 명시적으로 기재한다.

### [RT-2 · 높음] 회원가입의 자동 역할 부여가 감사 기록 없이 커밋되는 구간 발생 (INV-6 위반)

- **위치**: WP-2 작업 항목 1(AUTH-1), WP-6 착수 조건("WP-5 착수 전 완료 필수"), 주차 배분(WP-2는 2주차, WP-6은 4주차)
- **결함**: AUTH-1의 `MEMBER` 역할 자동 부여는 권한 변경이므로 INV-6(트랜잭션 내 감사 기록, 실패 시 롤백) 적용 대상이다. 그러나 감사 기록 함수는 WP-6 산출물이고, WP-6은 WP-5의 선행 조건으로만 걸려 있다. 계획대로면 2~3주차의 가입 처리들이 감사 기록 없이 커밋된다.
- **v2 반영 지시**: WP-6을 분할하라 — "트랜잭션 내 감사 기록 함수"(핵심 부분)를 **WP-2의 선행 조건으로 승격**하고(1주차 말~2주차 초 완료), 파티션 운영·append-only DB 권한 등 나머지는 현행 일정 유지. WP-2 DoD에 "가입 시 역할 부여가 감사 로그에 기록됨"을 추가.

### [RT-3 · 높음] CI 게이트 가동 시점의 내부 모순 — WP-0 DoD가 충족 불능이거나 빈 검사 통과가 됨

- **위치**: WP-0 작업 항목 3("즉시 가동: G-2, G-4, G-5"), WP-1 작업 항목 3(G-4 구현), WP-3 작업 항목 4(G-5 스크립트 구현)
- **결함**: G-4 검사 스크립트는 WP-1에서, G-5 스크립트는 WP-3에서 만든다. WP-0 시점에는 검사할 시드도 엔드포인트도 스크립트도 없다. "즉시 가동" 분류는 (a) WP-0 DoD를 충족 불능으로 만들거나, (b) 아무것도 검사하지 않는 워크플로를 "가동"으로 치는 눈속임이 된다. (b)는 도구를 용법대로 쓰지 않는 것으로 땜질 금지 4원칙 위반이다.
- **v2 반영 지시**: 게이트 가동 시점을 3단계로 정정 — WP-0: G-2·lint·typecheck·commitlint 가동 + G-1/G-3/G-4/G-5의 워크플로 자리만 생성(자리임을 명시) / WP-1: G-4 가동 / WP-3: G-5 가동 / WP-8: G-1·G-3 가동. 각 WP DoD에 해당 게이트의 "실패 실증" 항목을 이동 배치.

### [RT-4 · 중간] 2FA 강제의 두 가지 공백

- **위치**: WP-5 작업 항목 9, WP-1 작업 항목 2(최초 `SUPER_ADMIN` 시드), 기획서 §10.4
- **결함**: (a) "미등록이면 **다음 로그인 시** 등록 강제" 방식은 역할 부여 직후 기존 세션으로 2FA 없이 관리 행위가 가능한 창을 남긴다. (b) 시드 생성되는 최초 `SUPER_ADMIN`은 "최초 로그인 시 비밀번호 변경"만 강제되고 TOTP 등록 강제가 명시되어 있지 않다 — 최강 권한 계정이 2FA 없이 운영될 수 있다.
- **v2 반영 지시**: (a) `OPERATOR` 이상 역할 부여 시 대상자의 `perm_version`을 즉시 증가시켜 재로그인을 강제하고, 재로그인 흐름에서 TOTP 등록을 통과해야 세션 발급. (b) WP-1 시드 명세와 WP-2 로그인 흐름에 "최초 `SUPER_ADMIN`은 최초 로그인 시 비밀번호 변경 + TOTP 등록을 모두 완료해야 활성화"를 추가.

### [RT-5 · 중간] G-1 권한 매트릭스에 "비인증(anonymous)" 행 부재

- **위치**: WP-8 작업 항목 1
- **결함**: 매트릭스가 "역할 5종 × API"로 정의되어 비로그인 상태가 표에 없다. 보호 API가 실수로 `@Public`으로 바뀌는 변화를 표가 온전히 포착하려면 비인증 행이 필요하다.
- **v2 반영 지시**: 매트릭스를 "비인증 + 역할 5종(6행) × API"로 정정. 비인증 행은 `@Public` 선언 목록과 1:1로 대조한다.

### [RT-6 · 낮음] 정합성 3건

1. **근거 문서 파일명**: 표두의 `permission-system-spec.md`를 실제 파일명 `permission-system-spec-v1.3.md`로 정정 (발주자 파일명 버전 표기 규칙).
2. **부트스트랩 커밋 예외 미문서화**: 최초 커밋(2207f39)이 브랜치 보호 설정 전 `main`에 직접 들어갔다. 불가피한 부트스트랩이지만, "main 직접 push 금지" 규칙의 예외로 §5 검수 절차 또는 §6 변경 이력에 1회성 예외임을 기록하지 않으면 규칙과 이력이 모순으로 남는다.
3. **WP-4 착수 조건 vs 주차 배분**: 3주차 "WP-3·WP-4" 병행 표기가 WP-4 착수 조건("WP-2·WP-3 완료")과 충돌한다. "3주차 후반 WP-4 착수" 등으로 정정.

## 3. 발주자 확정 결정 (2026-08-07)

본 검토 과정에서 RT-1에 대해 발주자가 다음과 같이 결정하였다. v2 반영 시 이 결정을 근거로 삼는다.

> **비상 회수는 단계적으로 도입한다.** Phase 1은 운영 런북의 break-glass 절차(2인 입회, 전용 계정, 전량 감사, 사후 전 세션 무효화)로 대응하고, 쿼럼 승인 구조(SUPER_ADMIN 대상 조치는 타 SUPER_ADMIN 과반수/2인 승인으로 실행 — §9.5 승인 워크플로의 선행 구현)는 **Phase 3 확장으로 기획서에 예약**한다.

부수 효과: 이 결정은 기획서 개정 사항(§9.5 확장 목록에 쿼럼 승인 추가, §10.1 차단표에 break-glass 참조 추가, §13.3 관련 문서에 런북 명시)을 발생시킨다. 기획서 개정(v1.4)은 별도 건으로 진행한다.
