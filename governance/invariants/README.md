# 런타임 불변식 (RI-1 ~ RI-8)

기획서 §14.3의 불변식을 SQL 파일로 선언 관리한다(§15.2). 순찰 워커
(`apps/api/src/governance/patrol.service.ts`)가 10분마다 전부 실행한다.

## 파일 계약

- 파일명: `ri-<번호>-<슬러그>.sql`
- **위반 행을 반환하는 SELECT** 이며, 각 행은 `(ri_id, subject, detail)` 컬럼을 갖는다.
- 결과가 0행이면 이상 없음. 1행 이상이면 위반이다.
- `RI-1`·`RI-6` 처럼 **부재가 위반인 존재형**은 `NOT EXISTS` 로 합성 행을 만든다(WT-33).
  조건을 만족하는 행을 세는 형태로 쓰면 위반 시 0행이 되어 순찰이 "이상 없음"으로 읽는다.
- **`NOT IN (서브쿼리)` 금지** — NULL 하나에 조용히 0행이 되는 fail-open 을 만든다. `NOT EXISTS` 를 쓴다.
- 시드 정의(화이트리스트·시스템 역할)가 필요하면 `$1::jsonb` 컨텍스트로 받는다. **SQL 안에
  하드코딩하지 않는다** — 시드가 바뀔 때 검사만 뒤처진다(§15.1).

## 대응 단계 (WT-34)

| RI | 대응 | 이유 |
|---|---|---|
| RI-1 활성 SUPER_ADMIN 부재 | 즉시 호출 + 런북 | 자동 복구 불가 — 사람만 되돌릴 수 있다 |
| RI-2 자기 부여 | L-2 동결 후보 | 서비스를 우회한 직접 INSERT 정황 |
| RI-3 화이트리스트 밖 ALLOW Grant | **L-1 자동 회수** | 회수해도 정상 기능이 깨지지 않는다 |
| RI-4 고아 Grant | **L-1 자동 회수** | 정리 누락이며 남기면 되살아난다 |
| RI-5 교차 테넌트 | L-2 동결 후보 | 논리 참조라 FK 가 못 막는다 |
| RI-6 시스템 역할 변조 | 즉시 호출 + 런북 | 권한 체계의 기반이 흔들린 상태 |
| RI-7 감사 해시 체인 | L-3 보고 | 조사 대상이지 자동 조치 대상이 아니다 |
| RI-8 권한 화석 | L-3 보고 | 자동 삭제하면 관리자 교체마다 정상 공유가 끊긴다 |

## 자동 조치의 안전장치

- **blast-radius 상한**(기본 20행 또는 전체 Grant 의 1%): 넘으면 자동 조치를 멈추고 L-2 로 승격한다.
  대량 위반은 데이터 이상이 아니라 **불변식 정의가 현실과 어긋났다**는 신호다(WT-11).
- **미등록 리소스 타입은 "위반"이 아니라 "검사 불가"**: §9.1 로 추가된 신규 모듈의 정상 Grant 를
  전량 삭제하는 사고를 막는다.
- **회수는 SQL 이 아니라 `ResourceGrantService` 경유**: 회수 전 행 전체가 감사에 남아
  `scripts/restore-grants.ts` 로 되돌릴 수 있다.
- **fail-open 차단**: 화이트리스트·시스템 역할 정의가 비면 순찰이 실행 전에 멈춘다.
  검사 불가 상태를 "이상 없음"으로 보고하지 않기 위해서다.

## RI-7 의 검출 범위

`audit.audit_checkpoints` 가 하루치 로그의 해시를 봉인한다(매일 00:20). **체크포인트가 찍힌 뒤의
삭제·변조**를 검출하며, 당일 미체크포인트 구간은 범위 밖이다. 해시 계산은 DB 함수
`audit.day_digest`·`audit.chain_digest` 가 담당하고 생성·검증이 이를 공유한다(§15.1).
